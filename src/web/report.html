Executive summary

Two tasks use the same cleaned Baku residential listings: regression predicts logarithmic advertised price, while classification labels a listing premium when price is at or above the training-set median. The scratch NumPy tree performs strongly on the binary tier task and closely matches the scikit-learn reference. The AZN regression error remains substantial, particularly for the highest-priced listings. Our 30-tree bagging ensemble is the strongest model on both tasks: test R² 0.886, accuracy 0.934 and ROC-AUC 0.983 (see the run summary).

1. Dataset preparation and audit

The source has repeated scrape rows, mixed Azerbaijani text/numeric columns, absent measurements, price-derived fields and property categories with different feature availability. The pipeline keeps one latest dated record per normalized advert ID, scopes to Baku and three residential types, and applies the declared domain windows. The raw CSV remains untouched.

Loading audit…
Filtering decisions: price 10,000–5,000,000 AZN; floor area 10–2,000 m²; unit price 200–20,000 AZN/m². The source EDA informed these fixed limits before splitting. This is a limitation: the cutoffs were not selected from outside knowledge alone.

A further 544 reposted twins (the same advert posted again under a new ID) are removed during deduplication. Leakage-prone `total_price`, `unit_price`, descriptions, identifiers, raw address and owner/agency identifiers do not enter the model matrix.

2. Targets, split and leakage control

Task A: fit the tree to ln(price) to reduce the leverage of the long right tail, then report error in both logarithmic space and AZN. Task B: premium is price ≥ the training partition's median; the current threshold is — AZN. The split is a seeded random permutation (seed 42); premium shares stay close to balanced (0.500 / 0.505 / 0.501).

Train-only rules: room/coordinate medians, standardization statistics, frequent-location vocabulary and premium threshold are learned using train data and applied unchanged to validation/test. The raw source distribution was examined when selecting fixed cleaning bounds; this source-informed choice is disclosed.

3. Complete held-out results

Classification metrics use the positive “premium” class for precision, recall and F1. ROC-AUC uses continuous decision scores. Fit and prediction times are wall-clock results from this run, not portable performance guarantees.

Interpretation: Scratch and library tree results are close, supporting that the from-scratch split search is behaving plausibly on this data. Linear Pegasos obtains a slightly lower threshold accuracy than the tree but stronger ROC-AUC, indicating better score ranking at alternate thresholds. The RFF approximation and RBF SVC are weaker in this selected configuration.

4. Regression error analysis and feature signal

Currency-scale errors increase sharply in the top price quartile. That pattern explains why the model can have good log-space R² while still missing luxury-property prices by large AZN amounts. Quartile boundaries below come from the training target distribution; the reported errors use test rows.

5. Cross-validation and model selection

Five seeded folds are evaluated on the full training split. Settings were selected on validation, then fixed for the cross-validation diagnostic.

Loading cross-validation results…
CV caveat: the feature imputation/scaling and categorical vocabulary are prepared on the full training split before these folds are formed. Thus the cross-validation spread is useful as a stability diagnostic, but it is not a fully nested pipeline CV estimate. The held-out test result remains separate.

6. What is implemented

Decision treeNumPy classifier and regressor; Gini, entropy and MSE; numeric threshold search.
Linear SVMNumPy Pegasos on regularized hinge loss; support-vector and margin diagnostics.
Nonlinear SVMSeeded random Fourier map and the same Pegasos solver; 128 components.
Referencesscikit-learn trees, LinearSVC and RBF SVC for comparative benchmarking.

The nonlinear model scored below the linear model in this run. More complexity did not improve the result with the selected sample size, gamma and random-feature count. The implementation still demonstrates the required RBF approximation path and is reported with its weaker performance.

7. Honest limitations

!

Asking price

Listings are seller asking prices, not verified completed transactions. The model does not establish fair market value.

◷

Data age

The source is a 2024 scrape. It should not be presented as a current 2026 market estimate.

⌕

Source-informed filters

Fixed price and area windows were chosen after inspecting this dataset's distribution. This is disclosed selection bias.

∿

Generalization

Some locations are sparse; cross-ID ambiguous duplicate candidates remain; the CV preprocessing is not fully nested.
